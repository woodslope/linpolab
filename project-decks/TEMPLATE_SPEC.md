# LINPO LAB BWC 案例页模板规范

本文档是 `project-decks/` 下独立 HTML-PPT 案例页的统一模板基线。当前参考成稿为 `quanyu/index.html`。

## 1. Skill 链路

1. 使用 `ppt-content-structuring` Stage 1 讨论受众、目标、故事主线、页数和顺序。
2. 使用 `ppt-content-structuring` Stage 2 形成逐页规格，固定 `Text Area`、`Visual Slot`、`Icon Map`、`Layout Notes` 和 `Do Not`。
3. 使用 `BWC xixi ppt html` 生产 HTML，并在内容与图片确认后导出 editable PPTX。
4. 使用 `xiaobai-html-ppt` 做成稿体验验收、模板一致性检查和局部修复。

不从零散素材直接进入模板生产。`guizang-ppt-skill` 只可作为视觉参考，不替换 BWC 主生产链路。

## 2. 固定模板层

- 画布：`1672 x 941`，固定 16:9。
- 主题：每个项目在 BWC Black 与 BWC White 中锁定一种，同一 deck 不混用。Black 使用 `paper #000000`、`ink #f8f8f4`；White 使用 `paper #f7f7f2`、`ink #050505`；两者统一使用 `lime #b7ff00`。
- 字体：所有可见 HTML 文字使用 `BaiWuchangKeke`；PPTX 可编辑文字使用 `白无常可可体`。
- 背景：28px 细网格，根据已锁定的 Black/White 主题使用对应底色，不增加大面积渐变或高亮装饰。
- 页头：左侧 `LINPO LAB` 返回入口、中间项目切换、右侧项目年份和绿色页码胶囊。
- 页脚：左侧页码、中间进度点、右侧 `DESIGN / PAGE CODE`。
- 内容安全区：桌面基线为 `inset: 118px 76px 94px`，内容不得覆盖页头页脚。
- 交互：点击/方向键翻页，项目链接不触发翻页；图片支持大图查看；支持 `prefers-reduced-motion`。

## 3. 可变项目层

- 项目名称、年份、项目顺序和页面数量。
- 页面文案、图片、图标和页面代码。
- 内容区布局可按页面规格扩展，但不得修改固定模板层。
- 未开放项目使用不可点击状态；对应页面完成后再替换为真实相对链接。

## 4. 默认案例骨架

`LINPO LAB project-decks` 中的新作品集项目默认复用同一套案例证明节奏：

1. 项目封面。
2. 项目背景与设计课题。
3. 整体设计策略。
4. 按项目实际内容展开的设计证据页。
5. 项目成果与能力沉淀。

背景页顶部默认使用四项信息：`Role`、`Platform`、`Scope`、`Delivery Cadence`。个人角色、单人分阶段推进和关键时间关系优先写入这四项信息或现有背景文字，不默认新增角色页、时间线页或范围页。

作品集页面按证明逻辑组织，不强制按实际发生时间重排全部成果。如果时间关系影响事实准确性，在对应背景页或证据页用一句话说明，不因此破坏整体节奏。

用户提供大量图片、长文或已有页面时，仍先固定页面角色与占位规格，不从素材数量反推新模块。这条默认骨架只适用于 `LINPO LAB project-decks` 作品集案例，不扩展到课程、商业路演或其他 PPT 类型。

## 5. 案例页布局注册表

案例页是 BWC 的项目作品集扩展，不强制套用 Skill 演示中的四种内容布局。每页仍需使用以下稳定角色之一，避免长期保留无语义的 `CUSTOM`：

| Layout ID | 用途 |
| --- | --- |
| `CASE_COVER` | 项目封面：两行内标题、短说明、项目标签、主视觉 |
| `CASE_CONTEXT` | 背景、范围、挑战和约束 |
| `CASE_STRATEGY` | 3-5 项设计策略或方法 |
| `CASE_SPLIT` | 左侧说明 + 右侧项目证据图 |
| `CASE_SHOWCASE` | 大面积界面拼版或视觉证据 |
| `CASE_IMPACT` | 项目成果、能力沉淀或收尾总结 |

页面结构应由页面规格决定，不能为了视觉变化临时发明新模板。

`CASE_SPLIT` 的基础网格固定为左侧说明 `35%`、右侧证据视觉 `65%`、列间距 `42px`。同一项目和不同项目之间都默认复用这一宽度；不得因单页文字多少临时改成 `25/75` 或 `30/70`。只有真实素材比例或已确认的展示目标无法在标准网格中成立时，才在页面规格阶段明确记录例外。

`CASE_SHOWCASE` 的顶部标题栏固定为左对齐单行 `kicker`，格式为“英文页面类型 / 中文页名”，字号、字重、行高和绿色短线与全域项目保持一致。标题栏高度固定为 `42px`，与主视觉间距固定为 `20px`；右侧不放辅助标签、关键词或第二组说明。需要解释的内容进入图片内部编排或前后页面，不在标题栏增加新的信息层级。

## 6. 图片槽规则

- 所有可替换图片保留 `data-slot-id`、`data-asset`、`data-alt` 和 `data-image-mode`。
- `fit_full`：普通横向截图、界面拼版、短图和需要完整检查的证据图；完整等比显示，不加可见底板和 padding。
- `crop_top`：只有长页面或竖向长图在完整展示后不可读时使用；固定窗口、顶部对齐、底部裁切。
- 图片模式由 Stage 2 页面规格锁定，HTML 与 PPTX 保持一致。
- 原图、加工图、网站发布副本继续遵守各项目 `WORKFLOW.md` 的单一编辑源规则。

## 7. 验收门槛

- 逐页角色、页数和顺序与页面规格一致。
- 固定模板层在全部项目中一致。
- 标题不超过两行；无溢出、重叠、断字或不可读的小图。
- 图片全部加载，无 404、占位说明泄漏或错误裁切。
- 未开放项目没有伪链接；已开放项目使用真实相对路径。
- DOM/控制台无明显错误，键盘、点击、页码和大图查看可用。
- editable PPTX 的页数、顺序、文字、字体、图片模式和图标与 HTML 对齐。
- 只有 HTML 和 PPTX 都通过验收后，才进入最终交付目录。
