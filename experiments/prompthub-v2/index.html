01 / 实验速览

不是收藏更多文本，而是让提示词可以被找到、实例化和恢复。

验证对象

管理、填充、复制和备份的个人复用闭环。

当前状态

可运行的单文件本地网页应用。

关键边界

完整图文保存在本地，云同步为 BYOK 可选项。

证据结构

提示词库、新建、变量填充和备份设置四个状态。

02 / 提示词库主证据

分类、搜索、收藏和视觉参考图进入同一个可操作的库。

主界面证明提示词不再散落在文档和聊天记录里；演示条目只用于说明管理动作，不代表真实团队资产。

Library / 管理面

瀑布流卡片同时保留内容、分类、收藏和复制入口

搜索与分类负责定位，收藏负责高频复用，卡片操作负责复制、编辑与删除，视觉参考图也能随模板保存在本地。

03 / 模板到复用闭环

先保存结构，再在复制前把变量变成具体内容。

两个连续状态分别回答“模板如何进入库”和“模板如何变成这一次可用的提示词”。

Stage A / 结构化保存

分类、标题、正文变量与视觉参考被一起保存

新建表单允许正文包含变量占位符，并把视觉参考图作为本地资产关联到提示词。

模板层固定可复用结构；下一步才把变量替换为当前任务的具体输入。

Stage B / 即时实例化

复制前检测变量，填充后一次生成完整提示词

动态变量弹窗把主题、目标读者和原始内容等占位符变成这一次的具体内容，再进入剪贴板。

04 / 运行边界 · 存储与同步

完整图文留在本地，云端只承担可选的纯文本备份。

设置页证明数据恢复与同步入口存在，也明确图片和大体积资产不会默认上传。

Settings / 数据边界

本地导入导出与 GitHub Gist BYOK 同时存在

IndexedDB 保存完整图文；ZIP 提供物理备份；用户自行提供 Token 和可选密码后，才启用 Gist 纯文本同步。

current 截图 · 2026-07-12 · revision ba1614b

关键限制：Gist 不是默认云数据库；图片不上云，文本同步受体积限制，冲突合并和跨设备一致性仍需额外验证。

05 / 四步复用流程

从保存到复制，核心动作保持短而可检查。

01 · 分类保存记录标题、正文、变量与视觉参考。
02 · 搜索定位通过关键词、分类或收藏找到模板。
03 · 填充变量把占位符替换为当前任务内容。
04 · 复制使用生成完整文本并进入剪贴板。
IndexedDB 本地库

适合个人图文资产与离线使用，但浏览器清理和设备迁移需要可靠备份。

Gist 纯文本同步

BYOK 和可选 AES-GCM 降低托管依赖，但不是实时协作或完整媒体同步。

06 / 实验结论

个人提示词复用闭环已经成立，同步与大库可靠性还没有。

已成立

提示词可以被分类、搜索、保存变量、即时填充并复制，完整图文也有本地备份入口。

仍薄弱

同步冲突、密钥使用、超大库检索和跨设备一致性仍不足以支撑团队级知识库。

07 / 限制与下一步

先保证数据可恢复，再扩大模板与设备规模。

P0 · 数据恢复

验证导入导出、损坏备份、重复记录与恢复失败路径。

P1 · 检索与契约

强化大库搜索、变量命名、模板校验和异常占位符提示。

P2 · 跨设备体验

明确同步冲突、媒体边界和多设备状态一致性。
