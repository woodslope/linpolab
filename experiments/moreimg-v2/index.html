01 / 实验速览

核心不是“多生几张图”，而是把内容和视觉的责任分开。

输入

一篇有完整观点和结构的中文长文。

核心产物

卡片内容规格，以及一一对应的中文视觉提示词。

当前状态

真实 API 处理、历史记录与复制入口已跑通。

关键边界

模型输出仍需人工审查，提示词不等于最终图片。

02 / 核心界面证据

先锁定卡片内容规格，再把视觉表达作为独立产物。

两张真实结果截图是页面的主证据。它们证明产物已被分层展示和复制，不证明事实或出图质量会自动正确。

Stage A / 内容层

重构文章与卡片内容包可以分别检查

页面同时保留精修文章重构和三张知识卡片的内容责任，让顺序、标题、要点和不可误读关系先被固定。

内容层先回答“每张卡讲什么”；只有这一层可检查，视觉层才不会反过来改写事实。

Stage B / 视觉层

三条视觉提示词与三张卡片一一对应

提示词被单独呈现并提供复制入口，证明视觉构图、色彩和字体气质可以在不改写卡片内容的前提下继续生产。

03 / 运行证据与运行边界

配置让流程开始，窄屏只先证明入口可用。

模型、Endpoint 与系统指令由使用者配置

04 / 六阶段闭环

从准入判型到对应质检，每一步都保留独立责任。

六阶段顺序来自应用对模型输出的真实解析契约，不是为了页面展示追加的装饰流程。

01 · 准入判型判断文章是否适合拆成知识卡片。
02 · 事实与骨架标出不确定点，提取观点与结构。
03 · 文章重构调整主线和表达，保留可追溯内容。
04 · 卡片内容包固定页面顺序、标题、要点与关系。
05 · 视觉提示词为每张卡片生成对应的中文视觉指令。
06 · 对应质检检查卡片与提示词是否一一对应。
浏览器本地存储

API 配置、系统指令和最多 50 条历史记录写入 localStorage。这适合个人工具，不是团队数据层。

同源 CORS 转发

本地服务只把 `/v1/chat/completions` 转发到上游，不记录密钥或请求正文。它解决浏览器限制，不构成公共代理。

05 / 实验结论

双层产物闭环已经成立，输出稳定性和发布可靠性还没有。

已成立

中文长文可以经过分阶段处理，生成可分别检查和复制的卡片内容包与视觉提示词。

仍薄弱

模型输出格式、事实审查、公开部署和团队级密钥管理仍未闭环。

06 / 限制与下一步

先固化输出契约，再扩大文章和模型样本。

当前限制：一次成功运行只证明闭环可执行，不代表所有文章、模型和图像模型都稳定，也不代表事实审查可以省略。

P0 · 输出契约

P1 · 发布与配置
